# D1-550 眼在手抓取对准问题：外部模型调查材料

> 更新时间：2026-08-26
>
> 目的：向一个完全不了解本项目的高级 AI/机器人工程师提供足够上下文，请其判断是否存在比当前方案更简单、稳健的 PREGRASP 视觉纠偏办法。
> 当前关注对象：5 cm 黄色立方体。西葫芦和碗已走通真机抓取流程，但同样受机械臂几何精度与控制能力限制。

## 1. 希望外部模型重点回答的问题

我们已经能完成目标检测、地面拟合、俯视精定位、MoveIt 规划、夹爪闭合、抬升和 CARRY。当前最主要的失败源是：

> MoveIt/URDF 认为 PREGRASP 和垂直 DESCEND 已经对准，但真机两根手指可能偏离立方体两侧，下降时碰到立方体顶面并推动物体。

希望重点回答：

1. 在下述硬件和控制限制下，PREGRASP 后怎样用腕部 RGB-D 做最简单、稳健的闭环纠偏？
2. 怎样处理 PREGRASP 高度不固定，使“正确对准时的目标像素”随相机—物体距离变化的问题？
3. 是否能直接利用相机—TCP 固定外参和当前深度，在相机坐标系中构造误差，而不需要为多个高度采集经验像素或准确依赖 `base_link → TCP` 的 URDF/FK？
4. 如果必须标定，最小需要采集什么数据、多少样本、拟合什么模型？
5. 有无比“目标 mask 中心对准经验像素”更稳健但仍然很轻量的方法，例如检测两指内侧边界、估计夹爪中心线、局部 image-based visual servoing、在线 Jacobian 或一次性手眼残差标定？
6. 如何设置通过条件和失败条件，避免纠偏动作本身碰到物体或进入不可达区域？

我们优先要的是能尽快投入真机任务的工程方案，不追求论文层面的完整性。请尽量给出可按优先级实施的最小方案，并明确其假设、所需标定和失败模式。

## 2. 项目与任务概况

目标系统由 Unitree Go2、Unitree D1-550 六轴机械臂、二指夹爪和眼在手 Intel RealSense D435i 组成。任务是在平整场地拾取垃圾并投入垃圾桶。

三个目标类别：

- `yellow_cube`：黄色纸质立方体，边长 50 mm；
- `zucchini`：约 150 mm 长的长条物体；
- `bowl`：开口朝上的碗，碗口直径约 115 mm。

Go2 负责导航到目标附近并保持静止；机械臂子系统接收一个粗略三维提示点，自主完成主动观测、目标识别、抓取位姿估计、规划与执行。机械臂对外提供 ROS 2 Action：

```text
/arm/tasks/pick_object
/arm/tasks/drop_object
```

本材料只讨论 `pick_object` 中 PREGRASP 到 DESCEND 的真机对准问题。

## 3. 硬件和已知物理约束

### 3.1 机械臂与夹爪

- 机械臂：Unitree D1-550，当前真机序列号 `D1095`；
- 六个机械臂关节：`Joint0`～`Joint5`；
- 夹爪电机：`Joint6`；
- 夹爪净开口约 65 mm，而立方体边长 50 mm，横向允许误差很小；
- 真机 Joint6 实测机械范围约 `-32.2°～63.4°`，软件安全范围 `-30°～60°`；
- 没有可靠的力/力矩传感器，也没有指尖触觉；
- 当前只能依据关节角、相机和任务结果判断接触与抓取成功。

### 3.2 相机

- 相机：Intel RealSense D435i，序列号 `250122077729`；
- 安装方式：固定在 `Link6` 上，eye-in-hand；
- RGB：`1280×720 @ 30 Hz`；
- Depth：`848×480 @ 30 Hz`；
- 使用 RealSense 驱动提供的 aligned depth，输出到 RGB 像素网格；
- RGB/对齐深度内参：

```text
fx = 908.8550415
fy = 908.5066528
cx = 641.3519287
cy = 378.3876038
```

- 深度单位：`16UC1` 毫米；
- D435i 近距离深度不可靠，工程上把约 0.20 m 作为有效下界；
- 相机到 Link6 的外参来自实测手眼标定，而不是仅依赖 CAD。

实测的 `Link6 ← RGB optical` 齐次变换为：

```text
T_link6_rgb =
[[ 0.007802511223,  0.969491460227,  0.245000876253, -0.113433495391],
 [-0.999491412298, -0.000014772168,  0.031889128609,  0.033016808957],
 [ 0.030919857055, -0.245125087105,  0.968998273534, -0.051772117970],
 [ 0,               0,               0,               1]]
```

对应四元数 `xyzw`：

```text
[-0.098512702045, 0.076132192723, -0.700216133504, 0.702991111713]
```

RGB 光心在 Link6 中的位置约为 `[-113.433, +33.017, -51.772] mm`。相机与 TCP 不共点，因此正确抓取时，目标在 RGB 图像中一般不会落在主点或图像中心。

### 3.3 重力与地面

- Go2 调用抓取时保持静止；
- 当前真机没有 Go2，因此使用 D435i 加速度计估计重力方向；
- 地面由腕部 aligned depth 进行带重力法向约束的 RANSAC 拟合；
- 关键参数：距离阈值 8 mm、法向容差 15°、160 次迭代、最多 12000 点；
- 粗观测和精观测分别重新拟合地面，二者在 RViz 中用不同颜色显示；
- IMU 只约束法向，平面相对机械臂的高度由深度点拟合得到。

## 4. 软件与控制链路

### 4.1 上层

```text
YOLO 分割 + RGB-D 几何
        ↓
物体专用抓取策略
        ↓
MoveIt 2：IK、关节限位、自碰撞/Go2/地面碰撞、OMPL 与笛卡尔路径
        ↓
ROS 2 Action / ros2_control 适配
        ↓
自研 unitree-d1-control
        ↓
D1 板端串口舵机接口
```

MuJoCo 与真机共用上层感知和规划接口，但真机执行方式不同。

### 4.2 为什么没有执行完整 MoveIt 逐路点轨迹

D1 厂商接口不能可靠、平滑地执行常规高频多关节流式轨迹。我们测试过主机端和板端的 20～1000 Hz 短命令、仿遥操方式、不同 delay、五次多项式和限 jerk 插值；真机仍出现低频大晃动或高频小抖动，不适合精确下降。

当前真机执行每个任务阶段时，只取 MoveIt 轨迹的最终六关节目标，再发送一个完整 Joint0～6 的原生长段命令。这样比逐路点发送平滑且可用，但物理机械臂实际走的是舵机内部的关节空间插值，不严格沿 MoveIt 的笛卡尔轨迹。

### 4.3 两种当前可选的原生执行模式

两种模式最终都对每个舵机调用底层 `setRawAngle(target, delay_ms)`：

1. `uniform_joint_speed`
   - 每个关节使用相同平均角速度；
   - 位移小的关节先到，位移大的后到；
   - 整体较平稳；
   - 但 DESCEND 中工具轴姿态不能在全过程保持，曾观察到负责补偿的腕关节明显晚于其他关节完成。

2. `common_arrival`
   - 为所有运动关节设置近似相同到达时间；
   - 更能维持下降过程中的工具轴方向；
   - 但各关节有效速度不同，真机会产生明显晃动；
   - 测试把 DESCEND 等效速度从约 15°/s 降到 8、4、2°/s，晃动程度没有明显降低。

当前策略：普通阶段默认 `uniform_joint_speed`；DESCEND 显式使用 `common_arrival`。每次执行显式传模式，没有全局模式状态。

### 4.4 当前控制层已知异常

- 厂商高层 `funcode=2, mode=1` 曾偶发只执行完整七关节命令中的部分关节；
- 当前自研板端执行器改善了可观测性和命令所有权，但无法改善舵机自身的机械/闭环品质；
- 真机反馈约 9～10 Hz，ros2_control 可在 100 Hz 重复读取最新值；
- 单段目标平滑可用，但无法保证真实末端严格遵循 MoveIt 规划的中间笛卡尔约束；
- 接触阻挡时可能只表现为某关节未到位并最终超时，当前没有可靠接触检测。

## 5. 当前黄色立方体抓取流程

### 5.1 STOWED 与主动粗观测

机械臂固定收纳姿态：

```text
STOWED = [0, -1.54, 1.55, 0, 0, 0] rad
```

接收粗略目标点后，在重力水平面内搜索腕部相机观测位姿。搜索变量为水平偏角 `beta`、仰角 `alpha` 和距离 `d`，候选经 IK、限位、碰撞和完整规划筛选。

### 5.2 粗感知

- YOLO 只保留 `yellow_cube`、`zucchini`、`bowl` 三个已知类别；
- 只保留有有效深度验证、置信度达到阈值的实例；
- 在候选中选距离 RGB 光心最近者；
- 黄色立方体粗中心由 mask 中心射线与“拟合地面上方 25 mm 平面”相交得到。

### 5.3 精观测

- 将相机移动到估计目标上方；
- 光轴沿重力向下；
- 相机距物体约 0.35～0.60 m，逐项搜索可达候选；
- 重新获取 RGB-D；
- 重新拟合地面；
- 用 RGB mask 轮廓投影到已知立方体顶面，拟合正方形中心和边方向；
- 得到 cube 顶面中心和模 90° 的水平 yaw。

### 5.4 PREGRASP 与 GRASP 候选

- TCP approach vector 沿重力向下，倾角固定为 0°；
- PREGRASP 距离定义为 TCP 到立方体顶面的有符号距离，反重力方向为正；
- 从 `+80 mm` 到 `+15 mm`，每 5 mm 递减搜索；
- GRASP 距离定义同上，从 `-40 mm` 到 `-24 mm`，每 2 mm 搜索；
- 候选通过 IK、限位、碰撞和笛卡尔路径完整率检查；
- 笛卡尔路径最低完整率为 `0.999`；
- 立方体 yaw 的 90° 等价解按抓取深度、加权关节运动量等排序，避免不必要的腕部大转动；
- 真机到达 PREGRASP 后，会基于实际关节反馈重新计算 DESCEND 可达性，再选最深的可行抓取深度；
- 当前 DESCEND 使用 `common_arrival` 单段执行。

### 5.5 抓取后

夹爪闭合、夹持角度复检、垂直抬升 100 mm，然后进入：

```text
CARRY = [0, -1.54, 1.546, 0, -0.6, 1.57] rad
```

这部分已经多次在仿真和真机运行。当前讨论不涉及抓取后的流程。

## 6. 核心现实问题

### 6.1 URDF/FK 与真机不够一致

这是已知事实，而不是单次视觉误差：

- RViz 中工具轴与重力平行时，肉眼观察真机工具轴可能仍有明显倾斜；
- 一次西葫芦空载下降实验中，软件目标设为 TCP 离拟合地面约 1 mm，但真机指尖仍离桌面约 20 mm；
- 对 50 mm 立方体而言，约 5 mm 横向偏差已经可能使手指撞上顶面；
- 我们没有更准确的厂商 URDF，也无法直接重新做完整机械臂几何标定。

因此：

- `base_link → Link6/TCP` 的模型 FK 不能作为毫米级真值；
- `Link6 → camera` 的手眼外参相对可信；
- 相机直接看到的“物体相对腕部/夹爪”信息比模型计算的世界坐标更值得依赖。

### 6.2 单段关节执行不保证笛卡尔直线

MoveIt 可以规划严格垂直下降，但真机只执行该阶段终点。即使起点和终点工具轴都满足重力对齐，中间过程也由各关节舵机插值决定。

- `uniform_joint_speed`：平稳，但工具轴中途偏转；
- `common_arrival`：方向保持较好，但晃动可能碰到物体；
- 高频重放 MoveIt 路点：更卡顿或高频抖动，实测不可用。

因此视觉纠偏至少要让 PREGRASP 留出足够的横向安全余量；它不能修复执行器所有中间轨迹误差。

### 6.3 相机与 TCP 的偏置使“正确目标像素”依赖高度

相机固定在 Link6 上，但不在 TCP 中心。人工验证成功时，立方体 mask 中心约为 `(740, 440) px`，明显不在相机主点 `(641.35, 378.39) px`。

如果 PREGRASP 相机—物体深度改变，相同物理对准关系会投影到不同像素。因此不能把 `(740,440)` 作为所有高度的固定目标，也不能简单要求物体居中。

现有 PREGRASP 高度搜索又是必要的，因为固定深度（例如强制相机—物体深度 272 mm）可能 IK 不可达。

## 7. 2026-08-26 真机对准实验

### 7.1 实验设计

1. 自动运行到名义 PREGRASP，机械臂保持不动；
2. 记录 RGB、raw depth、aligned depth、CameraInfo、IMU、关节反馈和 TF；
3. 人工仅移动立方体，使其预计能被两指安全下降夹取；
4. 再记录相同数据；
5. 执行 DESCEND，但保持夹爪张开，不闭合、不抬升；
6. 操作者物理验收两指位置和下降过程。

### 7.4 DESCEND 后数据与人工结论

- DESCEND 后 mask 中心约 `(836.30, 594.72) px`；
- aligned depth 中位数约 205 mm；
- 有效深度像素明显减少，已经接近 D435i 近距离有效下界；
- 两根指尖分别位于立方体两侧；
- 下降过程中没有接触或推动立方体；
- 若此时闭合夹爪，可以可靠夹住。

因此，纠偏应在 PREGRASP 完成，不宜在 DESCEND 近距离阶段依赖深度继续闭环。

## 8. 已尝试或已否定的办法

### 8.1 仅靠提高 MoveIt/IK 精度

不足。MoveIt 在错误/不完整的机械模型上可以精确满足错误模型，不能消除真机系统误差。

### 8.2 给抓取姿态增加 2°～4° 倾角以避开奇异位形

仿真中可改善部分 IK；真机下降时会横向扫动手指，容易碰到立方体并推动它。当前三个物体都已改为只使用 0° 倾角。

### 8.3 全程执行 MoveIt 的高频中间路点

实测会引起严重卡顿或高频抖动。主机端、板端、20～1000 Hz、不同 delay、平滑插值均未达到可靠抓取要求。

### 8.4 DESCEND 使用相同关节角速度

运动较平稳，但各关节到达时间不同，工具轴在下降中途不能保持重力对齐。

### 8.5 DESCEND 使用共同到达时间并降低速度

工具轴保持较好，但真机晃动；把等效速度从 15°/s 降到 8、4、2°/s，晃动没有明显改善。

### 8.6 固定所有 PREGRASP 到同一个相机深度

理论上可以把正确目标像素固定下来，但某些目标位置下该固定深度可能 IK 不可达，因此不能作为通用前提。

### 8.7 所有高度共用固定目标像素 `(740,440)`

不成立。相机和 TCP 有明显平移偏置，正确投影会随深度变化。当前只有一个成功深度样本，不能把它当作全局标定。

## 9. 当前正在考虑、但尚未实施的方案

### 9.1 深度相关目标像素模型

保持现有可达 PREGRASP 高度搜索；到达实际 PREGRASP 后测量当前目标深度 `Z`，将正确目标像素拟合为：

```text
u_target(Z) = A_u + B_u / Z
v_target(Z) = A_v + B_v / Z
```

然后执行一到两次“小步移动—停止—重新观测”，只纠正横向图像误差。该形式来源于针孔投影下固定相机—TCP 几何偏置。

问题：当前只有 `Z≈272 mm → (740,440) px` 一个成功样本，至少还需两个不同可达高度的成功样本；而且真实工具姿态、相机朝向和机械结构误差可能使简单 `1/Z` 模型不足。

### 9.2 直接使用相机坐标系中的三维误差

从 aligned depth 和 mask 得到目标相对相机的三维位置，再根据已标定 `camera ↔ Link6/TCP` 构造“正确抓取时目标应位于相机中的三维位置”，只修正与 approach vector 正交的两个自由度。

潜在优势：天然考虑深度，不需要为每个高度记忆像素。潜在问题：TCP 相对 Link6 的模型和真实夹指几何仍可能不准；mask 中心深度不一定代表顶面中心；需要明确应对准的是物体顶面中心、TCP 轴还是两指安全通道。

### 9.3 直接检测夹指与物体的图像关系

在 PREGRASP RGB 中检测两根指尖/内侧边界与立方体左右边缘，直接判断物体是否位于两指安全通道内。这可能绕开不准确的机械臂 FK 和 TCP 定义。

潜在问题：相机安装位置、遮挡、反光和不同高度下的透视；可能需要简单的手指分割、标记或模板，而当前 YOLO 只训练了物体。

### 9.4 局部 image-based visual servoing / 在线 Jacobian

在 PREGRASP 处做很小的两自由度探测运动，从实际像素响应估计局部 Jacobian，再闭环减小误差。这样不依赖准确 URDF。

潜在问题：D1 的小运动执行存在量化、回差和晃动；调试复杂度高于一次静态映射。若采用，只考虑 stop-and-look，不考虑连续高频伺服。

## 10. 方案必须满足的工程约束

1. 不要求 D1 支持稳定的高频流式笛卡尔伺服；
2. 优先使用一到两次离散、小幅、停止后拍照的修正；
3. 修正只允许在 PREGRASP、深度仍可靠且手指未接近物体时进行；
4. 不把 `base_link → TCP` 的模型 FK 当作毫米级真值；
5. 可以信任 RGB-D 帧内的局部几何和实测 `Link6 → RGB` 手眼外参，但仍应允许残差标定；
6. 必须兼容 PREGRASP 高度搜索，不能强制某个固定高度可达；
7. 纠偏后仍需做 IK、限位和碰撞检查；
8. 一到两次修正仍不满足条件时，应中止并要求 Go2 调整位置，而不是无限迭代；
9. DESCEND 后相机深度接近 0.20 m 下界，不能依赖该阶段继续深度纠偏；
10. 第一版只需解决 50 mm 黄色立方体，之后再评估能否抽象给西葫芦和碗。

## 11. 事实、推断与未知项

### 已确认事实

- 相机内参和 Link6—RGB 外参来自连接的真机与实测标定；
- MoveIt/RViz 模型与真机末端存在肉眼和厘米级可见偏差；
- 同一 PREGRASP 机械臂姿态下，人工将立方体 mask 从约 `(786,449)` 移到 `(740,440)` 后，张开夹爪下降物理验收成功；
- 调整前后深度基本相同，关节和模型 TCP 基本不变；
- DESCEND 后深度接近 D435i 近距离下界；
- 逐路点流式控制和多种平滑方案在此 D1 上没有达到可靠抓取要求；
- `common_arrival` 比 `uniform_joint_speed` 更能保持下降工具轴方向，但会晃动。

### 强推断

- 本轮人工修正主要补偿了 PREGRASP 横向对准误差；
- 主要误差源包含机械臂几何模型、装配/FK 残差和实际舵机到位误差，而不仅是视觉分割；
- 在腕部局部坐标中闭环，比继续提高世界坐标规划精度更有希望。

### 尚未知

- 成功像素随深度是否足够符合 `A+B/Z`；
- 误差是否在不同机械臂姿态、不同目标方位下保持稳定；
- 相机—TCP 外参误差和机械臂 FK 误差各占多大比例；
- 两指在 PREGRASP RGB 中是否始终可稳定检测；
- D1 小幅横向纠偏的最小可靠位移、回差和重复性；
- `common_arrival` 下降的横向扰动统计分布和所需安全余量；
- 立方体 mask 的影子、反光和遮挡对中心估计的系统偏差。
