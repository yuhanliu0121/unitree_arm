# Real deployment configuration ownership

Deployment configuration uses three files:

| File | Purpose | Git |
| --- | --- | --- |
| `real_machine.yaml` | Complete development defaults and implementation-owned settings | Tracked |
| `real_machine.local.yaml` | Compact host/site override generated by `deploy/configure_d1_manipulation.sh` | Ignored |
| `real_machine.effective.yaml` | Validated merge consumed by launch files | Generated and ignored |

Run `./deploy/configure_d1_manipulation.sh`, fill the fields marked `REQUIRED`
in the generated local file, and then run it again with `--validate`. The daily
deployment launcher materializes the effective file automatically. A caller
may still pass an explicit, complete YAML with `--config PATH`.

The settings have three owners:

| Owner | Fields |
| --- | --- |
| Go2 integration | `deployment.ros_domain_id`, deployment override of `perception.model_path`, `arm.network_interface`, `arm.expected_ipv4_subnet`, `wrist_camera.driver_location`, camera stream rate/topics, and `site.go2_base_to_arm_base` |
| Arm/camera calibration | optional `arm.serial_no`, `wrist_camera.serial_no`, `wrist_camera.link6_to_camera_link`, hardware joint-limit profile, and object gripper profiles |
| Arm stack implementation | Native D1 DDS topics/domain, loopback ports, segment-controller timing, canonical frame names, and preflight thresholds |

The Go2 repository should carry the tracked defaults and generate its own local
overlay during deployment. It must not edit implementation defaults in launch files. Real
bringup rejects a missing perception model, unsupported camera profile, wrong
ROS domain, absent network interface, invalid TF/calibration, stale camera data,
or stale/out-of-limit arm feedback before activating controllers.

The checked-in and generated model path targets
`weights/mcislab_trash_collect.pt`, the frozen
model for the final wood cube, plush zucchini, and plastic bowl. Paper-object
development may explicitly select `weights/paper_objects_dev_best.pt`. The
generated overlay also carries the currently calibrated hand-eye transform.
An empty arm serial selects the base URDF; a non-empty serial only has an effect
after a matching per-arm profile is added and validated.
Do not commit site secrets or machine-local temporary paths. Absolute model
paths are recommended on the deployed computer; relative model paths are
resolved from the YAML location.
